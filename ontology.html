Ontology란?

지식의 구조를 AI가 이해할 수 있게 만드는 기술

개념 간 관계를 정의한 의미론적 지식 그래프

💡 Ontology의 정의

Ontology(온톨로지)는 철학 용어에서 유래했으며, "존재하는 것들과 그 관계에 대한 체계적 설명"을 의미합니다. 컴퓨터 과학에서는 특정 도메인의 개념들과 그 관계를 형식적으로 정의한 지식 모델입니다.

주어(Subject) → 관계(Relation) → 목적어(Object)

예: GE → produces → 비즈니스 방법론

🎯
노드 (Nodes)
개념, 엔티티, 사물. 예: GE, 잭웰치, 세일즈
↔️
엣지 (Edges)
관계, 연결. 예: includes, created_by, part_of
🏷️
속성 (Properties)
노드의 특성. 예: type, domain, status
📊
메타데이터
신뢰도, 출처, 생성일. 예: confidence: 0.95

🌐 시각화 예시

GE 비즈니스 방법론
↓ includes
세일즈 리더십 인재육성
↓ includes
Boss Managing 9가지 리더십 4E + V

📋 Ontology 구조 예시

1. 노드 정의 (Nodes)

node_id: N001 label: GE 비즈니스 방법론 type: Methodology domain: business_leadership description: GE에서 15년간 축적된 비즈니스 방법론 체계 status: active tags: [GE, 비즈니스, 방법론]

2. 관계 정의 (Edges)

edge_id: E001 source: GE 비즈니스 방법론 relation: includes target: 세일즈 프로세스 13가지 성공법칙 confidence: 0.95 source_file: GE의 세일즈 노트.pdf

3. Cypher 쿼리 (Neo4j)

// 노드 생성 CREATE (:Methodology { id: 'N001', label: 'GE 비즈니스 방법론', domain: 'business_leadership' }) // 관계 생성 MATCH (a {id: 'N001'}), (b {id: 'N002'}) CREATE (a)-[:INCLUDES {confidence: 0.95}]->(b) // 쿼리: GE와 관련된 모든 방법론 찾기 MATCH (ge:Company {label: 'GE'})-[:PRODUCES]->(m:Methodology) RETURN m.label

💎 Ontology의 가치

1. AI가 이해할 수 있는 지식

단순 텍스트가 아닌 구조화된 지식으로 AI가 추론 가능:

질문: "GE 방법론을 만든 사람은?"

온톨로지 기반 추론:
1. GE 비즈니스 방법론 → created_by → 심재우
2. GE 비즈니스 방법론 → includes → 변화리더십 101
3. 변화리더십 101 → created_by → 잭웰치

답변: "심재우 (전체), 잭웰치 (일부)"

2. 숨겨진 연결 발견

2-hop, 3-hop 관계로 비자명한 패턴 발견:

// 잭웰치와 간접 연결된 모든 개념 MATCH (jack:Person {label: '잭웰치'})-[*1..3]-(concept) RETURN DISTINCT concept.label // 결과: 9가지 리더십, Energy, Energize, Edge, Execute...

3. 자동화된 지식 통합

여러 출처의 지식을 자동으로 병합:

  • 출처 A: "GE → 4E+V"
  • 출처 B: "4E+V → Energy"
  • 자동 추론: "GE → 4E+V → Energy"

🔧 구축 방법

1. 수동 구축

  • 전문가가 직접 노드와 관계 정의
  • 높은 정확도, 시간 많이 소요
  • 예: 의료 온톨로지 (SNOMED CT)

2. 반자동 구축

  • NLP로 초안 생성 → 전문가 검토
  • 균형잡힌 접근
  • 예: 기업 내부 지식 그래프

3. 자동 구축

  • GPT, BERT 등으로 문서에서 자동 추출
  • 빠르지만 검증 필요
  • 예: Wikipedia → DBpedia
