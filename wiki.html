💡 Wiki의 본질

Wiki는 "빠른"을 뜻하는 하와이어 "wikiwiki"에서 유래했습니다. 1995년 Ward Cunningham이 만든 위키는 누구나 쉽고 빠르게 웹 페이지를 만들고 편집할 수 있는 혁명적인 시스템이었습니다.

🌟 성공적인 Wiki 사례

🌍 Wikipedia (위키피디아)

세계 최대의 백과사전

  • 6천만+ 개의 문서 (300+ 언어)
  • 월 250억 페이지뷰
  • 누적 기여자: 수백만 명
  • 예산: 거의 0원 (자원봉사 기반)

영향: 전통적인 백과사전(브리태니커 등)을 완전히 대체

💻 GitHub Wiki

소프트웨어 프로젝트 문서화

  • 모든 GitHub 저장소에 Wiki 제공
  • API 문서, 가이드, FAQ 작성
  • 마크다운 + Git 버전 관리

사용처: React, Vue, TensorFlow 등 주요 오픈소스

🏢 기업 내부 Wiki

조직 지식 관리 (KMS)

  • Confluence (Atlassian): 7만+ 기업 사용
  • Notion Wiki: 스타트업 표준
  • SharePoint Wiki: 대기업 레거시

효과: 온보딩 시간 50% 단축, 중복 질문 80% 감소

🎯 Wiki vs 전통적 문서

전통적 문서 (Word, PDF)

  • ❌ 고립된 파일: 각 문서가 독립적
  • ❌ 찾기 어려움: 폴더 깊숙이 숨겨짐
  • ❌ 구버전 문제: 여러 버전 혼재
  • ❌ 협업 어려움: 이메일로 주고받음
  • ❌ 업데이트 불편: 수정 후 재배포 필요

Wiki 방식

  • ✅ 연결된 지식: [[링크]]로 모두 연결
  • ✅ 즉시 검색: 전체 검색 1초
  • ✅ 항상 최신: 자동 동기화
  • ✅ 실시간 협업: 동시 편집 가능
  • ✅ 버전 자동 관리: Git 통합

💡 Wiki 작성 원칙

1. 원자성 (Atomicity)

하나의 페이지에 하나의 주제만 다룹니다.

  • ✅ 좋은 예: [[세일즈 기법 - 고객 니즈 파악]]
  • ❌ 나쁜 예: [[세일즈 모든 것]]

2. 링크 우선 (Link First)

관련된 개념은 무조건 링크로 연결합니다.

❌ "잭웰치가 만든 4E+V 모델은..." ✅ "[[잭웰치]]가 만든 [[4E+V 모델]]은..."

3. 계층 구조보다 네트워크

폴더 깊이보다 링크 연결이 중요합니다.

4. 살아있는 문서

완벽하지 않아도 일단 작성하고 점진적으로 개선합니다.

5. 백링크 활용

새 페이지 작성 시 관련 페이지에서 자동으로 링크 생성됩니다.

📊 Wiki의 효과

기업 사례 연구

  • Atlassian: Wiki 도입 후 이메일 질문 70% 감소
  • GitLab: 전체 회사 운영 매뉴얼을 Wiki로 공개
  • Notion: Wiki 기능으로 사용자 10배 증가

개인 생산성

  • 정보 검색 시간: 10분 → 10초 (100배 단축)
  • 지식 재사용률: 20% → 80% (4배 증가)
  • 온보딩 기간: 3개월 → 2주 (6배 단축)
